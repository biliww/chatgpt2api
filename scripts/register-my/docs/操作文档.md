# 浏览器注册机 · 操作文档（Runbook）

> 代码目录：`scripts/register-my/`
> 配套：`../account-record.example.json`（最终接口样例）、`../../docsMy/技术实现/注册/` 下的技术方案与接口说明
> 本文只讲**怎么跑起来、怎么看结果、出问题怎么办**。

---

## 0. 一句话流程

```
装依赖(playwright+chromium) → 准备配置 → 有头模式校准 1 个 → 无头批量 → 看 accounts.jsonl / 写号池
```

---

## 1. 前置依赖

本机需要：

| 依赖 | 说明 | 安装 |
|------|------|------|
| Python 3.11+ | 与项目一致 | 已随项目 |
| `playwright` | 浏览器驱动 | `pip install -r scripts/register-my/requirements-register-my.txt` |
| Chromium 二进制 | Playwright 不自带 | `playwright install chromium`（约 150MB，一次性） |
| 项目主依赖 | 复用 `services.register.mail_provider`（requests / curl_cffi） | 在主项目虚拟环境内运行即可 |

> ⚠️ 本环境**没有浏览器二进制、也无系统 Chrome**，首次运行前**必须**执行 `playwright install chromium`，否则会报 `Executable doesn't exist`。
> 若用项目既有虚拟环境（uv），请确保该环境里也装了 `playwright` 并装好 chromium。

**从仓库根目录执行（推荐）**，脚本会自动把仓库根加入 `sys.path`，从而能 import `services.*` 与同目录的 `browser/register/config`：

```bash
cd /path/to/chatgpt2api
```

## 2. 准备配置

两种方式，二选一：

### 方式 A：用独立配置文件（推荐，互不干扰）
复制样例，按需修改：

```bash
cp scripts/register-my/register-my.example.json scripts/register-my/config.json
```

### 方式 B：复用项目主配置
直接编辑根目录 `config-register.json`，在现有 `mail / proxy / total / threads` 基础上补一个 `browser` 段即可（结构见第 3 节）。运行时不加 `--config` 即默认读它。

---

## 3. 配置字段速查

`register-my.example.json` 完整结构如下（缺省项由 `config.py` 的 `DEFAULTS` 兜底）：

```jsonc
{
  "proxy": "",                         // 顶层代理，会被 browser.proxy 继承（未设时）
  "total": 1,                          // 本次注册数量
  "threads": 1,                        // 并发线程数（建议 ≤ 账号数，且有头模式别开太大）
  "mail": {
    "request_timeout": 30,
    "wait_timeout": 60,
    "providers": [
      { "enable": true,  "type": "tempmail_lol", "api_key": "" },   // 默认启用
      { "enable": false, "type": "cloudflare_temp_email", "domain": "xxx.workers.dev" }
      // 其他可选：ddg_mail / cloudmail_gen / duckmail / gptmail / moemail / inbucket / yyds_mail
    ]
  },
  "browser": {
    "headless": true,                  // true=无头（批量），false=有头（校准用）
    "proxy": "",                       // 空则继承顶层 proxy
    "user_agent": "Mozilla/5.0 ...",   // 默认内置一个桌面 UA
    "viewport": { "width": 1280, "height": 800 },
    "args": [],                        // 额外 Chromium 启动参数，如 ["--proxy-server=..."]
    "executable_path": "",             // 空则用 Playwright 自带的 chromium
    "timeout": 30000,                  // 页面操作超时(ms)
    "save_failure_screenshot": true,   // 失败时截图
    "screenshot_dir": "scripts/register-my/output/screenshots"
  },
  "output": {
    "write_pool": true,                // 成功是否写入本地号池(data/accounts.json)  ★见下方说明
    "jsonl_path": ""                   // 非空则额外写 JSONL 备份，如 "scripts/register-my/output/accounts.jsonl"
  },
  "log": {
    "level": "INFO",                   // DEBUG / INFO / WARN / ERROR。调试期设 DEBUG 打印详细步骤
    "to_console": true,                // 是否打印到终端
    "to_file": true,                   // 是否写入日志文件
    "file_path": "scripts/register-my/output/register.log"
  }
}
```

> ⚠️ **关于 `output.write_pool`**：代码里默认 `true` 会直接调用 `account_service.add_account_items()` 写号池。
> 首次跑时若想先落地文件复核，把它设为 `false`，并用 `jsonl_path` 落地文件；确认无误后再改 `true`，或走在线 `POST /api/accounts` 保存。

> 🪵 **日志级别**：`log.level` 控制打印粒度。`DEBUG` 会**逐步骤打印页面 URL、所有输入框/按钮结构、即将点击的按钮文案**（无图也能调试）；`INFO` 只打印关键进度；`ERROR` 仅错误。调试期建议 `DEBUG`。日志同时写 `register.log`（由 `to_file` 控制），终端与文件都带时间戳。

## 4. 运行命令

所有命令均从**仓库根目录**执行。

### 4.1 只校验配置（不注册）
```bash
python scripts/register-my/cli.py --config scripts/register-my/config.json --dry-run
```
会加载配置、校验邮箱服务商、打印生效参数后退出。

### 4.2 有头模式跑 1 个（首次必做：校准选择器）
```bash
python scripts/register-my/cli.py --config scripts/register-my/config.json --headed --total 1 --threads 1
```
- 会弹出真实浏览器窗口，你能看到每一步填写。
- **首次上线前必须跑通一次**，确认 `register.py` 里的邮箱/密码/验证码/姓名生日 选择器对得上当前 OpenAI 页面。
- 若某步卡住，失败会自动截图到 `scripts/register-my/output/screenshots/`，据此调整 `_signup` / `_fill_about_you` 的选择器。

### 4.3 无头批量
```bash
python scripts/register-my/cli.py --config scripts/register-my/config.json --headless --total 10 --threads 3
```
（`--headless` 是默认值，可省略。）

### 4.4 命令行临时覆盖配置
下列参数可覆盖配置文件，方便临时调试：

| 参数 | 作用 |
|------|------|
| `--config PATH` | 独立配置文件（默认读根目录 `config-register.json`） |
| `--total N` | 本次数量 |
| `--threads N` | 并发数 |
| `--proxy URL` | 代理（覆盖 `browser.proxy`） |
| `--headless` | 无头（默认） |
| `--headed` | 有头（需显示器） |
| `--dry-run` | 只校验不注册 |

示例（临时换代理 + 跑 5 个）：
```bash
python scripts/register-my/cli.py --config scripts/register-my/config.json --proxy http://1.2.3.4:8080 --total 5 --threads 2
```

## 5. 看结果

### 5.1 实时日志
运行期终端会逐行打印每个任务的进度（建邮箱 → 填邮箱 → 等验证码 → 验证码 → 填资料 → 填密码 → 落地 → 提取令牌）。
开 `DEBUG` 级别时，还会打印每步的**页面 URL 与输入框/按钮结构**，便于无图定位卡点。

> 📌 **实际注册流程**（已在浏览器中跑通验证，顺序可能因 OpenAI 版本浮动，代码已用自适应循环兼容）：
> `chatgpt.com` 注册入口（或直接 `auth/login` 入口，含 email 框）→ 填邮箱 → Continue →
> `auth.openai.com/email-verification` 收 6 位 OTP → 填验证码 → Continue →
> `about-you`（How old are you?：Full name + Age）→ Continue →
> 创建密码 → Continue → 落地 `chatgpt.com`（提取 access_token / session_token）。

### 5.2 落地文件（推荐先看这个）
配置 `output.jsonl_path` 后，每成功一条追加一行 JSON，结构见 `../account-record.example.json`：

```bash
cat scripts/register-my/output/accounts.jsonl
# 每行形如：
# {"email":"...","password":"...","access_token":"eyJ...","refresh_token":"...","id_token":"...","session_token":"...","source_type":"browser","created_at":"..."}
```

### 5.3 写号池（后续）
`output.write_pool=true` 时，成功记录会调用 `account_service.add_account_items()` 写入 `data/accounts.json`（按 `access_token` 去重），并自动 `refresh_accounts` 拉一次状态。

### 5.4 在线导入（另一种保存方式）
不想直接写号池，也可把 `accounts.jsonl` 里的记录 POST 到项目现有导入接口：
```bash
curl -X POST http://127.0.0.1:8000/api/accounts \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <ADMIN_KEY>" \
  -d '{"accounts": [ <accounts.jsonl 中的一条记录> ]}'
```

## 6. 故障排查

| 现象 | 原因 / 处理 |
|------|------------|
| `Executable doesn't exist` / 找不到 chromium | 没装浏览器二进制 → `playwright install chromium` |
| `ModuleNotFoundError: No module named 'playwright'` | 当前 Python 环境没装 → 在**项目虚拟环境**里 `pip install playwright` |
| 卡在“填写邮箱/密码/验证码”不动 | OpenAI 页面改版，选择器不匹配 → 用 `--headed` 跑，看失败截图，调 `register.py` 的 `_signup`/`_fill_about_you` |
| 收不到验证码 | 邮箱服务商被限/API key 失效 → 换 `mail.providers` 里启用的服务商，或检查 `api_key` |
| `registration_disallowed` | 注册被风控拦截（IP/设备/行为指纹）→ 换代理、降并发、拉长间隔；本机方案用真实浏览器+隐匿注入，比 API 方案更稳，但仍受 OpenAI 风控 |
| `access_token` 为空 / 提取失败 | 注册其实成功但落地页没切到 `chatgpt.com` 主站 → 检查 `_collect_tokens` 读取 `/api/auth/session` 的逻辑，必要时手动确认账号已可用 |
| `refresh_token` 为空 | next-auth 不向 JS 暴露 refresh token，属正常；账号过期后走密码重登兜底（号池已支持 `password_re_login`） |
| 截图目录很大 | `save_failure_screenshot` 默认开，定期清理 `scripts/register-my/output/screenshots/` |

---

## 7. 安全与合规提示

- 注册出的账号凭据（尤其是 `access_token`）等同于账号本身，**明文存 `accounts.jsonl` 请注意权限**，不要外传。
- `write_pool=true` 会直接改动项目号池 `data/accounts.json`，生产环境慎用，建议先 `jsonl_path` 落盘复核。
- 批量注册请遵守 OpenAI 使用条款与目标站点 robots/合规要求，控制频率与并发。
