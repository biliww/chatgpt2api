请根据一下内容修复


请重点修 OpenAI/Auth0 注册流程的最终 create_account 阶段。

现象：
邮箱创建、提交邮箱、提交密码、发送验证码、接收验证码、验证码校验都能成功，但最后 create_account 返回：
code=registration_disallowed
message="Sorry, we cannot create your account with the given information."

关键判断：
这不是邮箱收不到验证码，也不是验证码校验失败。
失败点在验证码通过后的最终创建账号阶段。

修复方向：
1. 对齐浏览器真实注册流程，不要只靠旧版代码直接 create_account。
2. 邮箱提交阶段需要补齐 authorize/continue 这一步。
3. create_account 请求必须同时带两个 Sentinel header：
   OpenAI-Sentinel-Token
   OpenAI-Sentinel-SO-Token
4. 不要手写拼接 Sentinel token，要加载当前官方 Sentinel SDK，并尽量复用 SDK 内部逻辑生成 token。
5. so-token 来源在 Sentinel req 返回的 so 字段里，生成方式和 proof-of-work 类似，也在官方 SDK 里。
6. so-token 的采集/observer 等待时间不要太短，按官方前端逻辑使用 5000ms。
7. create_account 前先请求 Sentinel req，flow 使用 oauth_create_account。
8. 然后从 Sentinel 返回的 requirements 里生成 Sentinel token 和 so-token。
9. create_account 请求头里带：
   OpenAI-Sentinel-Token: <SDK 生成的 Sentinel token>
   OpenAI-Sentinel-SO-Token: <SDK 生成的 so-token>

验证方法：
- 如果验证码已经通过，但 create_account 仍然 registration_disallowed，优先检查 Sentinel Token 和 SO Token 有没有按官方 SDK 生成。
- 日志里记录 token 长度、SDK 版本、so-token 是否生成即可，不要打印 token 明文。
- 修完后如果成功率从几乎 0 提高到 50% 左右，说明协议修复有效。

后续优化：
如果协议修完后仍有部分 registration_disallowed，不一定是协议问题，要按邮箱 provider/domain 分组统计。
某些临时邮箱域名会被最终风控拒绝。
例如某个固定临时邮箱域名成功率很低，停用该 provider 后成功率接近 100%。
所以最终还要支持按邮箱 provider/domain 统计成功率，并停用低成功率域名。
