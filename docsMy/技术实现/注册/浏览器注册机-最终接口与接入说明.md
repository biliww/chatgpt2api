# 浏览器注册机 · 最终接口（账号凭据）获取与项目接入说明

> 配套文档：`浏览器注册机技术方案.md`
> 配套样例文件：`scripts/register-my/account-record.example.json`
> 本文回答两个问题：① 浏览器方案能否拿到“最后的接口”（账号凭据）？② 这套凭据如何先落地到文件查看、后续再保存进项目号池管理。同时说明**后续可接入 Web 面板**（本期不实现）。

---

## 一、可行性结论：能拿到“最后的接口”

**可以。** 浏览器完成 OpenAI 注册并落地 `chatgpt.com` 后，认证态已写入页面的 `localStorage` 与 `cookie`。`scripts/register-my/register.py` 的 `_collect_tokens()` 据此提取 OAuth 令牌，**与现有 API 注册机（`services/register/openai_register.py` 经 `request_platform_oauth_token()` 换取）拿到的令牌同源、可直接互相刷新**。

| 字段 | 能否稳定获取 | 来源 |
|------|--------------|------|
| `access_token` | ✅ 稳定 | `chatgpt.com/api/auth/session` 的 `accessToken`（OpenAI 会话 JWT，含 `https://api.openai.com/auth` 声明，可直接用于 `backend-api` 调用） |
| `id_token` | ✅ 稳定 | `/api/auth/session` 的 `idToken`（Auth0 ID Token，JWT） |
| `refresh_token` | ⚠️ 可能为空 | next-auth 通常不向 JS 暴露 refresh token；尽力从 cookie 获取，拿不到则为空 |
| `session_token` | 🔶 可选 | cookie `__Secure-next-auth.session-token`（便于复用浏览器态） |

**关键说明**：`refresh_token` 可能为空不影响账号**立即使用**（号池以 `access_token` 为索引）。只是过期后续期需走**密码重登**（`account_service` 的 `password_re_login` 已支持用 `email/password` 回退登录），而非静默 `refresh_access_token`。若后续需要稳定续期，可在 `_collect_tokens` 中增加读取 Auth0 SPA 的 `localStorage` 键 `@@auth0spajs@@::<clientId>::<audience>::<scope>` 的 `body.refresh_token`（已知增强项，未在本期实现）。

## 二、最终接口（账号记录）长什么样

成功注册后，`register()` 返回的就是下面这条记录 —— 它**与 `account_service.add_account_items()` 的入参字段完全一致**（等同于 API 注册机的产出，仅 `source_type` 为 `browser`）：

```jsonc
{
  "email": "alice_wonder_8842@tempmail.lol",
  "password": "K7$mPq2wLx9vBn3d",
  "access_token": "eyJ...",
  "refresh_token": "ory_at_...",          // 可能为空
  "id_token": "eyJ...",
  "session_token": "eyJ...",               // 可选
  "source_type": "browser",
  "created_at": "2026-07-17T20:15:42.318000+00:00"
}
```

完整带注释样例见 **`scripts/register-my/account-record.example.json`**（可直接打开查看，里面逐字段标明了“怎么采集的”与“映射到号池的哪一处”）。

字段 → 号池（`data/accounts.json`）映射：

- `access_token` → **号池主键**：`account_service` 以它去重、索引，`refresh_access_token` / `get_available_access_token` 都靠它定位。
- `refresh_token` → 静默续期用；为空则依赖密码重登。
- `id_token` → 导出/校验用，`build_export_items` 要求 access/refresh/id 三者齐全才导出。
- `email` / `password` → 凭据，密码重登回退使用。
- `source_type: "browser"` → 与 API 注册机的 `"web"` 区分来源。

## 三、先落地到文件（现在就能看）

`cli.py` 已内置“写文件”出口，配置 `output.jsonl_path` 即可把每条成功记录追加写入 JSONL，**每条就是第二节那条结构**：

```jsonc
// config-register.json 或 register-my 专属配置
{
  "output": {
    "jsonl_path": "data/register-my/accounts.jsonl",   // 落地文件，每行一条账号记录
    "write_pool": false                                  // 暂不直接写号池（见第四节）
  }
}
```

运行：

```bash
python scripts/register-my/cli.py --config config-register.json --total 1
# 成功后查看：
cat data/register-my/accounts.jsonl
```

该文件就是“最后的接口”明文集合，便于你先确认字段、格式是否符合预期。

## 四、后续如何“保存到项目中管理”（调用接口）

本期只落地文件、不自动写号池；但**保存接口已就绪**，后续两种调用方式任选其一：

### 方式 A · 离线（脚本内直接写号池）
`cli.py` 的 `output.write_pool: true` 即启用（代码已写好，默认关）：

```jsonc
{ "output": { "jsonl_path": "data/register-my/accounts.jsonl", "write_pool": true } }
```

启用后，每成功一条就调用：

```python
from services.account_service import account_service
account_service.add_account_items([record])      # 按 access_token 去重写入 data/accounts.json
account_service.refresh_accounts([record["access_token"]])   # 顺带拉一次配额/状态
```

### 方式 B · 在线（走项目现有导入接口）
Web 面板已有账号导入入口，等价于：

```bash
curl -X POST http://127.0.0.1:8000/api/accounts \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <ADMIN_KEY>" \
  -d '{"accounts": [ <第二节那条记录> ]}'
```

> 两条路径最终都落到 `account_service.add_account_items()`，去重主键为 `access_token`，并与现有号池、配额、刷新、导出流程完全打通。

## 五、后续可接入 Web 面板（本期不实现，仅说明）

按你的要求，**本期不把浏览器机接入 Web 面板**，但架构上完全可平滑接入，预留方式为：

1. **配置开关**：在 `config-register.json` 增加 `mode: "browser" | "api"`，面板据此切换调用 `scripts/register-my` 还是现有 API 注册机；`mail` / `browser` / `output` 配置段已兼容。
2. **日志复用**：浏览器机的 `make_logger(sink)` 已支持把日志推到外部 sink，面板可接同一套 SSE 通道（`/api/register/events`）实时展示进度。
3. **调度方式（二选一）**：
   - 轻量：面板通过子进程 `subprocess` 调用 `cli.py`，读取其 `accounts.jsonl` 输出再写号池；
   - 深度：把 `BrowserRegistrar` / `run_one` 直接 import 进 `services/register/`，复用 `account_service` 与线程池，省去进程边界。
4. **界面**：在 `web/src/app/register/` 增加“浏览器模式”Tab 与无头/有头、并发数、结果落盘路径等控件。

> 结论：浏览器机作为**独立脚本**本期已完整可用；接入面板属于 P2 增强，按需再行开发，不影响当前“落地文件 → 后续调用接口保存”的主链路。
